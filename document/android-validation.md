# Android 디자인 v4 검증 기록

기초 검증일: 2026-10-11. 2026-10-13 출시 후보 상태를 아래에 덧붙였습니다. 제목의 v4는 **디자인 시안 버전**이며 Play의 `versionCode=4`와 다릅니다. 승인된 `yourcolor-design-v4.html`을 Kotlin 네이티브 앱으로 반영했습니다. 이 기록은 초기 ML Kit·자동 구도 앱의 이전 검증을 대체합니다. 현 구현은 자동 구도를 적용하지 않으며, U²-NetP를 앱에 포함합니다.

2026-10-11의 홈·로딩·피사체 화면 정리 후 API 37의 일반 화면에서 실제 캡처로 하단 여백 24dp와 편집 헤더의 세로 중심을 확인했습니다. API 24 에뮬레이터도 재부팅에 성공해 당시 구현의 기능 테스트를 실행했습니다. 이후 코드 3에서 API 24 홈 시작 버튼이 잘리는 문제가 발견됐으므로 아래의 과거 화면 검사 통과는 최종 출시 후보의 검증으로 간주하지 않습니다.

## 2026-10-13 출시 후보 상태

- Play 내부 테스트 초안에 새 업로드 키로 서명한 코드 2·3 AAB가 접수됐습니다. 두 번들 모두 출시되지 않았습니다. 업로드 키 대기와 Android 개발자 인증 단계는 끝났고 대시보드에는 앱이 **등록됨 / 소유권 확인됨**으로 표시됩니다.
- 코드 3에서 API 24 홈 시작 버튼의 하단 잘림을 발견했습니다. 수정 후 코드 4 (`versionName=2.0.0`)를 새 후보로 빌드·검증합니다. 코드 4의 테스트, 서명, SHA-256, Play 접수와 사전 출시 보고서는 아직 완료로 기록하지 않습니다.
- Play의 공식 서명 코드 1 APK를 확보했습니다. 이를 설치한 뒤 코드 4로 업데이트하는 검사는 별도로 확인해야 합니다. 전용 16KB 페이지 크기 에뮬레이터 실행, 폴더블 접힘·펼침 및 회전의 최종 후보 검증도 결과가 나온 뒤 기록합니다.
- 계정별 `adi-registration.properties`는 배포 소스와 AAB에서 제거해야 합니다. 빌드 설정에 파일 존재 시 실패하는 검사가 추가됐으며 최종 번들 내용 검사로 확인합니다.

## 결과

- 당시 `assembleDebug`, `assembleDebugAndroidTest`, `testDebugUnitTest`, `lintDebug`, `assembleRelease`, `bundleRelease` 성공. 당시 APK·AAB는 새 업로드 키로 서명했으며 이후 Play가 같은 키로 서명한 AAB를 접수했습니다. 이 빌드 결과는 코드 4의 검사 결과가 아닙니다.
- 순수 상태 단위 테스트 **7개 통과**.
- Android 7.0/API 24 ARM64에서 테스트 **9개 통과·1개 건너뜀**. 건너뛴 항목은 Android 10 이상의 MediaStore 저장 도중 화면 재생성 검사입니다.
- Android 17/API 37 ARM64에서 테스트 **10개 통과**. 저장 준비 중 화면 재생성 후 파일 생성도 검사합니다.
- 아래 화면 프로필에서 시작·선택·편집·피사체 보정·저장·저장 버튼 접근성 검사. Activity 재생성 시 조절값과 보정 초안 유지, 도구 전환 시 스크롤 유지도 검사합니다.
- Lint **오류 0**. 남은 경고는 라이브러리 새 버전 알림, 그리기 중 객체 할당, KTX 스타일 제안, ChromeOS용 x86 ABI 제안 등입니다. API 24에서 호출할 수 없는 API 오류는 수정했습니다.
- APK의 16KB ZIP 정렬 통과. 포함된 ARM64/ARMv7 ONNX 공유 라이브러리의 ELF LOAD 세그먼트도 16KB 정렬을 확인했습니다. **16KB 메모리 페이지 기기에서 실행한 결과는 아닙니다.**
- 최종 manifest에 `INTERNET` 권한이 없음을 실행 중 패키지 정보로 검사했고, 번들 모델로 세 샘플을 실제 추론했습니다.
- 릴리스 APK를 **로컬 검증 전용 디버그 키**로 임시 서명해 API 37 에뮬레이터에 설치·실행했습니다. 이 파일은 Play 업로드에 사용하지 않습니다.

## 화면 조건

아래는 **제조사 실기기가 아닌 Android 에뮬레이터의 화면 조건**입니다. 해상도는 기기 자료를 참고했고 density는 논리 화면 크기 검증을 위한 지정값입니다. 화면 배율·제스처 바·컷아웃·One UI·LG 펌웨어를 동일하게 재현한 것이 아닙니다.

| Galaxy S26 Ultra | 1440×3120 | 560 | API 37 | 세로 편집·저장 |

| S26 Ultra 큰 글씨 | 1440×3120 | 560, 글자 배율 1.3 | API 37 | 주요 컨트롤과 화면 흐름 |

V20 기준은 [LG V20 공식 발표](https://www.lg.com/global/newsroom/news/corporate/lg-takes-the-multimedia-mobile-experience-to-the-next-level-with-v20/)를 참고했습니다. S26 Ultra 화면 해상도는 [Samsung Developer](https://developer.samsung.com/galaxy-emulator-skin/galaxy-s.html), 최신 Fold8/Flip8과 커버 화면은 [삼성 공식 발표의 사양표](https://news.samsung.com/us/samsung-galaxy-z-fold8-ultra-fold8-flip8-foldables-perfected-every-way-of-living/)를 사용했습니다. Fold8 내부 폭은 개발자 스킨 페이지의 1828px와 뉴스룸의 1848px가 달라, 이 테스트는 뉴스룸의 1848px 기준입니다.

Flip 커버 크기의 테스트는 **커버 화면에서 일반 앱을 실행할 수 있다는 보장이 아닙니다.** 실제 커버 앱 실행 정책과 카메라 가림 영역은 실기기 확인이 필요합니다. 접힘 영역을 피하는 WindowManager 코드가 있지만 실제 힌지 이벤트·Flex Mode 전환은 아직 검증하지 않았습니다.

## 실제로 검사한 동작

1. 모델 결과가 도착해도 방향·길이·모양은 바꾸지 않음. 이전 사진의 결과는 무시.
2. 내 사진은 효과 없이, 선택 화면의 샘플은 직선·길이 86으로 열림. 홈 샘플의 자동차 길이 100은 위쪽 끝까지 연결.
3. 원본의 피사체 마스크 안 픽셀만 추출하여 네 방향으로 늘림. 피사체 원본 색을 다시 합성하고 바깥 배경은 유지.
4. EXIF 회전 후 같은 4:5 크롭 사용. 미리보기와 JPG 저장에서 같은 조절값 사용.
5. Android 10 이상에서 실제 MediaStore JPG를 생성·읽기 확인. 테스트가 만든 파일은 검사 후 삭제.
6. Android 7에서 문서 URI 출력 코드를 FileProvider URI로 호출해 실제 JPG 쓰기·읽기 확인. **시스템 문서 선택창에서 사용자가 저장 위치를 고르는 전체 UI 조작은 미검증**.
7. 보정 영역 추가·삭제, 완료와 취소의 분리, 실행 취소, 회전 후 보정 초안 유지.
8. 시작선 드래그를 한 번의 실행 취소로 복구. 두 번째 손가락이 닿으면 임시 브러시 획을 버려 확대 동작이 사진에 칠해지지 않음.
9. 저장 시 조절값·마스크 고정. 샘플 인식은 실제 U²-NetP 추론으로 별도 검사.
10. 화면 크기별로 4:5 사진 비율, 고정 상단 저장 버튼, 스크롤 후 최종 저장 버튼 접근, 도구 전환 스크롤 유지 검사. 홈의 시작 버튼은 Flip 커버 크기를 제외한 프로필에서 화면 안에 완전히 보이는지도 확인.
11. 저장 이미지 준비 중 Activity가 재생성되어도 저장이 한 번만 이어지는지 검사(Android 10 이상).

API 37 에뮬레이터에서 홈·로딩·편집·피사체 다듬기·모양·내보내기를 실제 화면 캡처로 확인했습니다. 홈에서는 로고·사진·하단 버튼의 좌표를 유지하면서 제목을 내려 사진과 버튼 사이의 여백을 맞췄습니다. 피사체 도구는 한 카드로 묶어 중복 설명과 화면 밖으로 밀린 취소 행을 없앴습니다. 편집 헤더의 뒤로·저장 버튼은 같은 세로 중심에 놓입니다. 원본 비교, 시작선 이동, 모양·바탕 선택, 피사체 브러시와 완료, 시스템 사진 선택, 사진 보관함 저장을 직접 조작했습니다. 저장한 JPG 파일을 다시 읽어 1440×1800px를 확인했습니다. 캡처는 `design/references/android-parity-2026-10-11/revision/`에 있습니다. 아래 화면 프로필 자동 검사에서 생성하는 PNG는 View 트리를 Canvas로 그린 이미지라 시스템 상태 표시줄은 다를 수 있습니다.

## 메모리와 속도

API 24 테스트 이미지의 앱 힙 한도는 48 MiB였습니다. 초기 1200px 미리보기와 원본 크기 합성 마스크에서는 메모리 부족이 재현됐습니다. 낮은 메모리 기기의 마스크를 최대 너비 320px로 줄이고 미리보기·출력 크기를 제한한 뒤 기능과 화면 테스트를 통과했습니다. 일반 기기의 합성 마스크는 최대 너비 960px입니다. 모델 추론과 사진 입출력은 메인 스레드 밖에서 실행합니다.

샘플 작품·마스크는 같은 모델과 렌더러로 미리 생성해 앱에 포함합니다. 첫 화면은 모델 초기화·세 번의 추론을 기다리지 않습니다. 사용자 사진에는 번들 모델로 새로 추론합니다.

에뮬레이터 추론 시간은 호스트 부하와 가속 환경의 영향을 크게 받아 **V20 또는 삼성 실기기의 처리 시간으로 안내하지 않습니다.** Snapdragon 820의 실제 속도·발열·지속 편집·복잡한 사진의 경계 품질은 남은 실기기 확인 항목입니다.

## 재현과 증거

- 실행 안내: [`android/README.md`](../android/README.md)
- 기능 테스트: `android/app/src/androidTest/java/com/robotics/yourcolor/EditorIntegrationTest.kt`
- 입력 테스트: `android/app/src/androidTest/java/com/robotics/yourcolor/PhotoCanvasGestureTest.kt`
- 화면 테스트: `android/app/src/androidTest/java/com/robotics/yourcolor/DeviceLayoutTest.kt`
- 화면 조건 자동 검사: `android/tools/validate_profiles.py` (에뮬레이터만 허용, 종료 시 기존 해상도·density·글자 배율 복구)
- 화면별 검수 PNG·결과 JSON: `android/app/build/outputs/device-proofs/`
- 빌드·테스트 로그: `android/app/build/outputs/validation/`
- 최종 개발용 APK: `android/app/build/outputs/apk/debug/app-debug.apk`

검사 결과물과 APK는 생성 파일이므로 Git에서 제외합니다. 실기기 시험은 이번 출시의 필수 조건에서 제외했습니다. 2026-10-13 현재 Play 내부 테스트 초안의 코드 2·3은 공개되지 않았고 코드 4 검증이 남았습니다. 위의 16KB ZIP/ELF 정렬은 이전 후보의 결과이며 **16KB 페이지 크기 실행 성공을 의미하지 않습니다.** 삼성 One UI의 실제 힌지 전환·성능과 LG V20 동작은 실기기를 확보한 뒤 확인합니다. 프로젝트 저장 기능이 없어 프로세스가 완전히 종료되면 편집은 복구되지 않습니다.
