# YourColor 디자인 시안 03 — 피사체에서 가로·세로로 늘리기

2026-10-11. 사용자의 “피사체를 기준으로 쭉 위로 올리는 것” 피드백을 반영한 **HTML 제안 시안**이다. `yourcolor-design-v3.html`에서 동작한다. Android 구현이나 출시 기능 확정은 아니다.

## 가로·세로 방향 추가 (2026-10-11)

사용자가 현재의 피사체에서 늘어나는 느낌을 유지하면서 다른 축도 지원하도록 요청했다. **위·아래·왼쪽·오른쪽** 선택을 추가했다.

- 위·아래는 실제 사진의 가로 한 줄을, 왼쪽·오른쪽은 세로 한 줄을 추출한다. 배경을 섞지 않도록 같은 피사체 마스크로 범위를 제한한다.
- 직선·펼침·곡선 모두 네 방향에 적용한다. 피사체와 원본 사진은 회전하지 않고 스트레치만 선택한 방향으로 그린다.
- 화살표와 드래그/키보드 조절 축이 방향에 맞춰 바뀐다. 연두색 점은 해당 축의 시작선을 옮기며, 가능한 한 바깥 끝을 유지한다.
- 방향 변경도 실행 취소/다시 실행과 사진별 상태에 포함한다. 모델을 다시 실행하거나 사진을 외부로 보내지 않는다.
- 두 슬라이더는 방향에 중립적인 ‘늘리는 길이’와 ‘끝부분 펼침’으로 표시한다. 곡선에서는 두 번째가 ‘휘어지는 정도’다.
- 모바일 화면에는 방향 버튼 한 줄을 추가하고 작업 영역 높이를 조정했다.

검증: 모바일 375×812에서 왼쪽 직선 드래그 86 → 60 및 실행 취소로 86 복원, 세로 시작선 x=480 → 567 이동과 끝 x=139 유지, 오른쪽 펼침과 아래쪽 곡선 합성 확인. 아래 방향 키보드 조작으로 길이 86 → 90 증가 확인. 가로 결과의 1440×1800 저장 미리보기에서 안내/조작점이 제외됨을 확인했다. 네 방향 좌표 변환·시작점 고정·끝 위치 보존 계산도 검사했다. JPG 다운로드와 V20 실기기 성능은 검증하지 않았다.

## 이전 수정 — 위로 늘리기


장식적인 궤도·잔상 대신 **피사체의 가로 한 줄 → 위로 늘리기 → 같은 시작점에서 변형하기**로 편집을 정리했다. 이전 v3 실험 소스는 `archive/v3-orbit/`, v2는 기존 파일에 보존했다.

- **직선:** 선택한 높이에서 실제 사진의 RGB 한 줄을 추출해 수직으로 반복한다. 임의 색상이나 금속 명암으로 대체하지 않는다.
- **펼침:** 같은 줄의 밑부분은 피사체에 붙이고 위쪽 폭을 넓힌다.
- **곡선:** 같은 밑부분을 유지한 채 위로 올라갈수록 휘어진다. 좌우 드래그로 휘는 위치도 조절한다.
- 색을 가져오는 폭은 해당 높이의 실제 분리 마스크로 정한다. 피사체 사이 빈 공간은 투명하게 남긴다. 선택한 줄에 피사체가 없으면 배경을 대신 늘리지 않고 시작선 이동을 안내한다.
- 스트레치를 먼저 그리고 분리한 피사체를 앞에 합성한다. `피사체를 앞에 유지` 스위치는 기존대로 보정 화면에 있다.
- **위쪽 화살표 또는 사진 빈 곳을 위아래로 끌기:** 시작선은 고정하고 길이만 변경한다. `위로 늘리기` 슬라이더로도 조절한다.
- **아래쪽 연두색 점을 위아래로 끌기:** 색을 가져오는 높이를 바꾼다. 위쪽 끝의 높이를 가능한 한 유지한다. `시작선 바꾸기`를 누르고 원본 사진에서 직접 위치를 고를 수도 있다.
- **윗부분 펼침 / 휘어지는 정도:** 두 번째 슬라이더로 조절한다. 직선에서는 비활성화한다.
- 사진별 편집 상태, 실행 취소/다시 실행, 원본 비교, 바탕 선택, 피사체 보정, JPG 저장 미리보기를 유지했다.

샘플은 설명을 위한 수동 초기값을 쓴다. 자동차부터 보여준다. **가져온 사진은 효과 미선택 상태로 시작하며 피사체만 분리한다.** 효과 적용은 사용자가 선택한다. 드래그·효과 변경으로 모델을 다시 실행하지 않는다.

## 범위와 제한

- 기기 내 분리는 기존 `u2netp` + ONNX Runtime Web Worker를 재사용한다. 모델과 런타임을 로컬에 동봉했으며 사진 업로드나 원격 추론 API가 없다. [출처와 라이선스](README.md#분리-모델과-런타임-출처).
- 샘플 배치를 위해 투명 이미지의 범위를 읽지만, 편집에 쓰는 마스크는 샘플과 가져온 사진 모두 모델로 추론한다.
- 320px 입력의 작은 모델이라 머리카락·가는 팔·줄기·복잡한 배경에서 경계가 빠지거나 밝은 테두리가 남을 수 있다. 이번 수정은 픽셀 스트레치 연결 방식과 조작을 고친 것이며 모델 정확도 개선이 아니다. 보정 브러시를 유지했다.
- 정지 이미지 편집이다. Android/V20에서의 성능은 HTML 검증으로 확인할 수 없다. 네이티브 코드는 변경하지 않았다.
- 작업 영역은 4:5, 원본 캐시는 960×1200. 가져온 사진은 전체가 보이도록 맞춘다. 크롭·피사체 재배치 도구는 이번 범위에 없다.
- 1440×1800 JPG는 캐시를 확대한 결과다. 원본 해상도 보존을 의미하지 않는다. 편집 조작점·안내·영문 라벨은 저장하지 않는다.
- 편집은 메모리에만 유지되므로 새로고침하면 사라진다.
- 기존 다운로드 코드를 유지했다. 이전 검증에서 인앱 브라우저의 blob 링크 열기가 보안 정책으로 차단되어 재시도하지 않았다. 이번에는 저장 미리보기까지만 확인했다.

## 실행

저장소 루트에서:

```sh
python3 legacy/design-prototypes/build_v3.py
python3 -m http.server 8767 --bind 127.0.0.1 --directory legacy/design-prototypes
```

http://127.0.0.1:8767/yourcolor-design-v3.html

편집 소스: `src/v3.html`, `src/v3.css`, `src/v3.js`. 로컬 모델·런타임과 공용 `src/segment-worker.mjs`를 함께 제공해야 한다. 빌드에 npm 설치는 필요 없다.

## 검증

- JavaScript 문법과 HTML의 ID 연결 확인. 1280×900 데스크톱과 375×812 모바일에서 배치 확인. 브라우저 오류·경고 로그 없음.
- 375×812 모바일 화면에서 실제 드래그: 길이 86 → 59, 시작 높이 948px 유지. 실행 취소로 86 복원.
- 시작점 직접 드래그: 샘플링 높이 948 → 895px, 폭 811 → 678px로 변경되며 상단 높이 133px 유지. 실제 색도 해당 줄로 바뀜.
- 자동차·인물·꽃의 모델 마스크와 피사체에서 이어지는 결과 확인. 직선·펼침·곡선 모두 같은 시작점을 사용하는 모습 확인.
- 일반 JPG를 파일 선택기로 가져오면 원본 상태로 시작하고, 기기 내 분리 후 사용자가 직선을 선택하면 피사체의 한 줄에서 스트레치가 생성됨을 확인. QA 사진은 rembg 공식 예제이며 제품 샘플에 추가하지 않았다.
- 저장 미리보기는 조작점/안내 없는 1440×1800 Canvas. 실제 JPG 파일 다운로드 완료는 이번 검증에 포함하지 않는다.
- 글꼴·샘플 이미지·모델의 기존 출처와 라이선스를 유지한다. `provenance.json` 참고.
