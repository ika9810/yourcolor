# Android 디자인 v4 검증 기록

기초 검증일: 2026-10-11. 코드 4 검증: 2026-10-13. 코드 6 게시 상태 갱신: 2026-10-14. 제목의 v4는 **디자인 시안 버전**이며 Play의 `versionCode=4`와 다릅니다. 승인된 HTML v4 시안을 Kotlin 네이티브 앱으로 반영했습니다. 이 기록은 초기 ML Kit·자동 구도 앱의 이전 검증을 대체합니다. 현 구현은 자동 구도를 적용하지 않으며, U²-NetP를 앱에 포함합니다.

2026-10-11의 홈·로딩·피사체 화면 정리 후 API 37의 일반 화면에서 실제 캡처로 하단 여백 24dp와 편집 헤더의 세로 중심을 확인했습니다. API 24 에뮬레이터도 재부팅에 성공해 당시 구현의 기능 테스트를 실행했습니다. 이후 코드 3에서 API 24 홈 시작 버튼이 잘리는 문제가 발견됐으므로 아래의 과거 화면 검사 통과는 최종 출시 후보의 검증으로 간주하지 않습니다.

## 2026-10-14 코드 6 게시 상태

- 코드 5(2.0.1)는 Play에 업로드됐지만 비활성 상태였고, 브랜딩 업데이트는 코드 6(2.0.2)으로 제출했습니다. 변경사항 8건의 검토가 끝나 2026-10-14 오전 2:51(미 동부) 프로덕션에 자동 게시됐습니다. 출시 비율은 100%입니다. 한국어·미국·캐나다 스토어에서 2.0.2, 앱 이름, 아이콘, 기능 그래픽, 첫 스크린샷을 확인했습니다.
- 코드 6 릴리스 APK·AAB를 생성했습니다. APK 출력 메타데이터에 `com.robotics.yourcolor`, `versionCode=6`, `versionName=2.0.2`가 기록돼 있습니다. AAB SHA-256은 `d1c76a3c94f3661f3f9bf783d8668610c8933ef5372ebe9424f5b6ed6e5a73ff`, APK SHA-256은 `95fce7984eb2e10ad5f1901a6fbc99d50afa375f127b0d4a38257f56fe05ab0b`입니다. `jarsigner -verify`는 AAB 서명을 확인했고, 번들에 계정별 `adi-registration.properties`는 없습니다. 앱 내 한국어·영어 개인정보처리방침의 버전 1 시점 표현도 번들에서 확인했습니다.
- 아래 API 24·37·16KB 페이지 크기 계측 검사 및 화면 프로필은 **코드 4 공개 빌드의 기록**입니다. 코드 6에 대해 같은 전체 검사가 재실행됐다는 뜻은 아닙니다. 코드 6의 새 브랜드 자산은 앱 아이콘·홈 로고·영문 홈 스크린샷과 스토어 그래픽에서 별도 확인했습니다. 게시 초기 Android vitals와 사전 출시 보고서에는 판단 가능한 새 결과가 없었습니다.

## 2026-10-13 코드 4 공개 검증

- 코드 3에서 API 24 홈 시작 버튼의 하단 잘림을 발견해 수정했습니다. 코드 4 (`versionName=2.0.0`)를 새 업로드 키로 빌드해 내부 테스트와 프로덕션에 출시했습니다. 사용자 승인에 따라 관리형 게시에서 15개 변경사항을 게시했고 Play는 **`변경사항이 게시되었습니다.`**라고 확인했습니다. 프로덕션 대시보드는 **`활성 / 최신 출시 버전 4 (2.0.0)`**, 177개 국가/지역을 표시하며 출시 탭은 **`Google Play에 제공됨`**, 콘솔 표시 게시 시각은 2026-10-13 오후 2:47입니다.
- 코드 4에서 `assembleRelease`, `bundleRelease`, `lintVitalRelease`가 성공했습니다. AAB SHA-256은 `528d88439777f5940bb74011094b170611cc96f279643c04135000e1246595ab`, 로컬 릴리스 APK SHA-256은 `a021b9fd289fbb046ffaa2dc68e9fff47369c7281d4721017bb3710a486fa694`입니다. 계정별 `adi-registration.properties`는 배포 소스와 AAB 목록에 없고, 파일이 다시 생기면 빌드가 실패합니다. 코드 4 수정 후 `testDebugUnitTest`와 `lintDebug` 재실행 결과는 아직 없습니다.
- API 24 에뮬레이터에서 연결 테스트 **9개 통과·1개 건너뜀**(Android 10 이상 전용 검사), API 37에서 **10개 통과**했습니다. API 36의 **16KB 페이지 크기 에뮬레이터**에서도 최종 전체 계측 검사 **10개가 한 번에 통과**했습니다([보존한 로그](evidence/16kb-api36-final-v4-green.txt)). 앞선 실행에서는 스크롤 위치가 30px 대신 22px으로 측정돼 레이아웃 검사 1개가 실패했으며, 단독 재실행과 최종 전체 재실행에서 통과했습니다.
- 화면 프로필 결과 JSON의 **8개 조건**이 통과했고, API 24 화면 조건은 별도 검사했습니다. Pixel Fold 에뮬레이터의 `OPENED`·`CLOSED`·`HALF_OPENED` 전환과 가로 회전에서 편집 상태가 유지됐습니다. Play Bundle Explorer도 코드 4의 **16KB 페이지 크기 지원**을 감지했습니다. 실제 Z Fold One UI·힌지 동작은 확인되지 않았습니다.
- Play의 공식 서명 코드 1 APK에서 시작해 코드 4 공식 Play 서명 APK로 `install -r` 업데이트가 성공했습니다. 버전 코드 1→4, 기존 설치 시각과 앱 전용 마커 파일 SHA-256 유지, 코드 4 정상 실행을 [업데이트 로그](evidence/play-v1-to-v4-update.txt)에 기록했습니다. Play 서명 코드 4 APK SHA-256은 `074c9e8b106196f38c8ed7377e02ac8bd70feeb6eaa74d587f369bc86ec91951`입니다.
- Play 제출 ID 2가 `출시 준비` 상태가 된 뒤와 프로덕션 게시 직후에도 사전 출시 보고서 개요에는 **‘아티팩트를 업로드하여 사전 출시 보고서 생성’** 안내만 표시됐습니다. 게시 직후까지 보고서 결과는 없었습니다.

## 2026-10-11 기준 결과 (이전 후보)

- 당시 `assembleDebug`, `assembleDebugAndroidTest`, `testDebugUnitTest`, `lintDebug`, `assembleRelease`, `bundleRelease` 성공. 당시 APK·AAB는 새 업로드 키로 서명했으며 이후 Play가 같은 키로 서명한 AAB를 접수했습니다. 이 빌드 결과는 코드 4의 검사 결과가 아닙니다.
- 순수 상태 단위 테스트 **7개 통과**.
- Android 7.0/API 24 ARM64에서 테스트 **9개 통과·1개 건너뜀**. 건너뛴 항목은 Android 10 이상의 MediaStore 저장 도중 화면 재생성 검사입니다.
- Android 17/API 37 ARM64에서 테스트 **10개 통과**. 저장 준비 중 화면 재생성 후 파일 생성도 검사합니다.
- 아래 화면 프로필에서 시작·선택·편집·피사체 보정·저장·저장 버튼 접근성 검사. Activity 재생성 시 조절값과 보정 초안 유지, 도구 전환 시 스크롤 유지도 검사합니다.
- Lint **오류 0**. 남은 경고는 라이브러리 새 버전 알림, 그리기 중 객체 할당, KTX 스타일 제안, ChromeOS용 x86 ABI 제안 등입니다. API 24에서 호출할 수 없는 API 오류는 수정했습니다.
- 당시 APK의 16KB ZIP 정렬 통과. 포함된 ARM64/ARMv7 ONNX 공유 라이브러리의 ELF LOAD 세그먼트도 16KB 정렬을 확인했습니다. 이 당시에는 16KB 페이지 크기 실행을 하지 않았고, 위에 기록한 코드 4 검증에서 별도로 실행했습니다.
- 최종 manifest에 `INTERNET` 권한이 없음을 실행 중 패키지 정보로 검사했고, 번들 모델로 세 샘플을 실제 추론했습니다.
- 릴리스 APK를 **로컬 검증 전용 디버그 키**로 임시 서명해 API 37 에뮬레이터에 설치·실행했습니다. 이 파일은 Play 업로드에 사용하지 않습니다.

## 실제로 검사한 동작

1. 모델 결과가 도착해도 방향·길이·모양은 바꾸지 않음. 이전 사진의 결과는 무시.
2. 내 사진은 효과 없이, 선택 화면의 샘플은 직선·길이 86으로 열림. 홈 샘플의 자동차 길이 100은 위쪽 끝까지 연결.
3. 원본의 피사체 마스크 안 픽셀만 추출하여 네 방향으로 늘림. 피사체 원본 색을 다시 합성하고 바깥 배경은 유지.
4. EXIF 회전 후 같은 4:5 크롭 사용. 미리보기와 JPG 저장에서 같은 조절값 사용.
5. Android 10 이상에서 실제 MediaStore JPG를 생성·읽기 확인. 테스트가 만든 파일은 검사 후 삭제.
6. Android 7에서 문서 URI 출력 코드를 FileProvider URI로 호출해 실제 JPG 쓰기·읽기 확인. **시스템 문서 선택창에서 사용자가 저장 위치를 고르는 전체 UI 조작은 미검증**.
7. 보정 영역 추가·삭제, 완료와 취소의 분리, 실행 취소, 회전 후 보정 초안 유지.
8. 시작선 드래그를 한 번의 실행 취소로 복구. 두 번째 손가락이 닿으면 임시 브러시 획을 버려 확대 동작이 사진에 칠해지지 않음.
9. 저장 시 조절값·마스크 고정. 샘플 인식은 실제 U²-NetP 추론으로 별도 검사.
10. 화면 크기별로 4:5 사진 비율, 고정 상단 저장 버튼, 스크롤 후 최종 저장 버튼 접근, 도구 전환 스크롤 유지 검사. 홈의 시작 버튼은 Flip 커버 크기를 제외한 프로필에서 화면 안에 완전히 보이는지도 확인.
11. 저장 이미지 준비 중 Activity가 재생성되어도 저장이 한 번만 이어지는지 검사(Android 10 이상).

API 37 에뮬레이터에서 홈·로딩·편집·피사체 다듬기·모양·내보내기를 실제 화면 캡처로 확인했습니다. 홈에서는 로고·사진·하단 버튼의 좌표를 유지하면서 제목을 내려 사진과 버튼 사이의 여백을 맞췄습니다. 피사체 도구는 한 카드로 묶어 중복 설명과 화면 밖으로 밀린 취소 행을 없앴습니다. 편집 헤더의 뒤로·저장 버튼은 같은 세로 중심에 놓입니다. 원본 비교, 시작선 이동, 모양·바탕 선택, 피사체 브러시와 완료, 시스템 사진 선택, 사진 보관함 저장을 직접 조작했습니다. 저장한 JPG 파일을 다시 읽어 1440×1800px를 확인했습니다. 과거 캡처는 `legacy/design-prototypes/references/android-parity-2026-10-11/revision/`에 있습니다. 화면 프로필 자동 검사에서 생성하는 PNG는 View 트리를 Canvas로 그린 이미지라 시스템 상태 표시줄은 다를 수 있습니다.

## 메모리와 속도

API 24 테스트 이미지의 앱 힙 한도는 48 MiB였습니다. 초기 1200px 미리보기와 원본 크기 합성 마스크에서는 메모리 부족이 재현됐습니다. 낮은 메모리 기기의 마스크를 최대 너비 320px로 줄이고 미리보기·출력 크기를 제한한 뒤 기능과 화면 테스트를 통과했습니다. 일반 기기의 합성 마스크는 최대 너비 960px입니다. 모델 추론과 사진 입출력은 메인 스레드 밖에서 실행합니다.

샘플 작품·마스크는 같은 모델과 렌더러로 미리 생성해 앱에 포함합니다. 첫 화면은 모델 초기화·세 번의 추론을 기다리지 않습니다. 사용자 사진에는 번들 모델로 새로 추론합니다.

에뮬레이터 추론 시간은 호스트 부하와 가속 환경의 영향을 크게 받아 **V20 또는 삼성 실기기의 처리 시간으로 안내하지 않습니다.** Snapdragon 820의 실제 속도·발열·지속 편집·복잡한 사진의 경계 품질은 남은 실기기 확인 항목입니다.
